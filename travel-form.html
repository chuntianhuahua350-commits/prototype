汇联易表单调整原型

原型看填写和审批页面，流程图看步骤，需求文档看三份说明，附件模板看 PDF 和 Excel。

差旅申请单流程

没选工单就按普通出差提交，后面的回填和入库都不做。客户名称用表单上原有字段，系统不改。

1售后

在汇联易打开差旅申请单，填写日期、事由、客户名称。

2关联工单
  1. 按汇联易文档格式开发老系统接口。售后一点下拉，汇联易就来调我们。返回格式以外部值列表为准：messageKey 显示工单号和客户名称，value 是工单号，remark 放设备编号。接口编码 OUT_ENUMERATION。
  2. 用当前申请人匹配工单处理人。现在可以这样做：回调里的 employeeID 就是当前申请人。老系统处理人在 apply_and_user.user_name。开发先确认这两个是不是同一个工号。是，就只返回这个人作为处理人的工单。不是，就在对接服务自己的库建一张映射表，把汇联易工号对应到老系统 user_name，上线前导入售后人员。不要用姓名匹配。建单人不是处理人的工单不出现。
  3. 商务在汇联易后台配置这个接口。操作说明在同一篇文档：先到「系统管理 → 值列表 → 外部值列表」新建「售后工单」，再到「系统管理 → 其他设置 → 外部接口回调」新增回调，API_CODE 填 OUT_ENUMERATION，地址填开发给的外网地址。地址规则见回调模式。差旅申请单上的「关联工单」选外部值列表、先按单选，绑这个值列表。
3提交

售后点提交。选了工单时，提交前只检查工单是否存在、当前申请人是不是处理人。附件这时还没有，不拦截。

4汇联易回调

提交成功后汇联易推送 TRAVEL_APPLICATION_SUBMIT。开发按差旅申请提交做接收接口。商务在同一处「外部接口回调」再加一条，API_CODE 填 TRAVEL_APPLICATION_SUBMIT，配置方式见回调模式。

5我们接口接收回调

外层 message 是加密的，用官方 Java 解密库解开。解开后的正文就是差旅申请单详情。从里面取申请单号 businessCode、申请人 employeeID，以及「关联工单」字段里的工单号。先返回成功，再做后面的回填。

6调用汇联易接口回填

工单基本信息和设备信息用申请单自定义控件值更新：工单类型、计划工期、现场描述、设备编号、设备名称、设备型号。工单 PDF 用单据附件批量上传，挂到「工单信息附件」，entityType=1001。字段都靠商务提供的 fieldCode。

7工单和差旅申请单的关联入库

对接服务自己的库记下：申请单号、工单号、已上传附件的 OID。报销单提交时用申请单号找到这张工单，再回填报销单上的工单信息和打卡 Excel。单据撤回后重新提交，按新工单覆盖这条记录。

差旅报销单流程

售后不在报销单上再选工单。工单只从已关联的差旅申请单带过来。客户名称仍用报销单上原有字段，系统不改。

1售后

打开差旅报销单，上传发票、车票。

2关联申请单

这是汇联易现有字段，不用新增。售后选之前提交的那张差旅申请单。

3提交

售后点提交。填写页上看不到工单字段、工单 PDF 和打卡 Excel。

4汇联易调用回调接口

提交成功后汇联易推送 EXPENSE_REPORT_SUBMIT。开发按报销单提交做接收接口。商务在「外部接口回调」增加这一条，配置方式见回调模式。外层 message 用官方 Java 解密库解开，正文是报销单详情。

5判断关联的申请单是否已有工单

从报销单详情的 applicationList 取出关联的申请单号，再查差旅申请单详情，或查上一步入库的申请单号和工单号。没有关联申请单，或申请单上没有工单号：结束，不回填，也不提醒。

6有工单则回填

工单基础信息和设备信息用报销单自定义控件值更新：工单号、工单类型、计划工期、现场描述、设备编号、设备名称、设备型号。两份附件用单据附件批量上传，entityType=1002：工单 PDF 进「工单信息附件」，打卡 Excel 进「打卡记录附件」。打卡只取报销申请人本人，日期用申请单的出发日到返回日。字段都用报销单自己的 fieldCode。

报销单也要能直接看到工单信息。这些字段都是提交后由系统写入，售后不在报销单上再选工单。关联申请单、事由、报销凭证如果表单上已经有，保持原样。

提交后怎么知道要回填

汇联易提交成功后，把加密的 message 推到我们的回调地址。用官方 Java 解密库解开（PublicMsgCryptUtil.zip，文档要求把下载地址复制到新标签页打开）。

差旅申请提交写明，解开后的正文就是差旅申请单详情。从里面取这三项：

  1. businessCode：这张申请单的单号，回填和上传附件都用它
  2. applicant.employeeID：当前申请人的汇联易工号。下拉和提交校验都用它对应老系统工单处理人，对不上的工单不能选
  3. custFormValues：找到「关联工单」的 fieldCode，value 就是下拉返回的工单号。没有值则不回填

下拉数据来自外部值列表，API_CODE 为 OUT_ENUMERATION。
